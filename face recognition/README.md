# سامانه حضور و غیاب چهره‌ای (Face Attendance)

موتور: **InsightFace buffalo_l** — تشخیص چهره SCRFD + امضا ArcFace R100 (بردار ۵۱۲ بُعدی) + تطبیق cosine similarity. دیتابیس SQLite. اجرای کامل روی CPU (بدون نیاز به GPU).

## نصب
```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
```
مدل‌ها (~۲۸۰ مگابایت) اولین بار که کد اجرا شود از GitHub به `~/.insightface/models/buffalo_l` دانلود می‌شوند.
`requirements.txt` شامل `openpyxl` (فایل اکسل گزارش) و `jdatetime` (تاریخ شمسی در گزارش) هم هست.

## اجرا
ساده‌ترین راه: دابل‌کلیک روی **`run-dashboard.bat`** — داشبورد را با پایتون درستِ پروژه (`\.venv`) بالا می‌آورد، آدرس را در مرورگر باز می‌کند و اگر سرور متوقف شود **خودکار دوباره اجرااش می‌کند**. پنجره سیاه باید باز بماند.

اگر چیزی در پنل کار نکرد، اول با **Ctrl+F5** صفحه را کامل تازه کنید (نسخه قدیمی صفحه در کش مرورگر می‌ماند).

```bash
# ۱) ثبت‌نام دانشجو با وب‌کم (۶ نمونه از زوایای مختلف) — نام را لاتین وارد کنید
python enroll.py --name "Ali Rezaei" --code 9912345

# یا ثبت‌نام از پوشه عکس‌های آماده
python enroll.py --name "Ali Rezaei" --code 9912345 --images photos/9912345

# ۲) مانیتور زنده: تشخیص چهره + ثبت ورود؛ خروج پس از غیبت طولانی خودکار ثبت می‌شود
python monitor.py --camera 0 --threshold 0.4 --absence-minutes 15
# کلیدها: Q خروج | S اسنپ‌شات | R گزارش روز

# ۳) گزارش روزانه + خروجی CSV
python report.py --date 2026-10-13

# ۳b) فایل اکسل گزارش یک روز (حاضر/غایب + نمودارها) -> reports/
python export.py --date 2026-10-13

# ۴) وب‌داشبورد فارسی (کارت‌های خلاصه، افراد داخل، رویدادها، مدیریت دانشجویان) — هر ۵ ثانیه خودکار تازه می‌شود
python dashboard.py   # سپس در مرورگر: http://127.0.0.1:8050
```

## مدیریت دانشجویان از پنل داشبورد
در داشبورد دکمه **«+ افزودن دانشجو»** و در هر ردیف جدول دانشجویان دکمه‌های **«ویرایش»** و **«حذف»** وجود دارد. فیلدها: نام، شماره دانشجویی (یکتا)، رشته تحصیلی، ایمیل، شماره تماس و **عکس**.

REST API همان پنل:

| متد | مسیر | کاربرد |
|---|---|---|
| `GET` | `/api/students` | فهرست دانشجویان + تعداد نمونه چهره + وضعیت امروز |
| `POST` | `/api/students` | افزودن دانشجو |
| `PUT` | `/api/students/<id>` | ویرایش اطلاعات |
| `DELETE` | `/api/students/<id>` | حذف دانشجو به‌همراه رکوردهای حضور و غیاب، عکس و بردارهای چهره |
| `GET` | `/api/settings` | تنظیمات ساعت مجاز و گزارش اکسل |
| `POST` | `/api/settings` | ذخیره ساعت‌های مجاز، فعال/غیرفعال کردنشان و زمان‌بندی گزارش |
| `GET` | `/photo/<id>` | فایل عکس دانشجو |
| `POST` | `/api/facecheck` | پیش‌بررسی یک عکس (بدون ذخیره): چهره پیدا شد یا نه، چرا، و زاویه سر (`yaw`/`pitch`) برای راهنمایی مرحله‌به‌مرحله وب‌کم |
| `POST` | `/api/identify` | تست تشخیص: این عکس با آستانه داده‌شده به کدام دانشجوی گالری می‌خورد (نام، کد، درصد شباهت) |
| `GET` | `/api/gallerycheck` | وضعیت اعتبارسنجی گالری: نمونه چهره و عکس هر دانشجو + چه کسانی هرگز شناسایی نمی‌شوند |
| `POST` | `/api/export` | ساخت همین الانِ فایل اکسل یک روز |
| `GET` | `/api/reports` | فهرست فایل‌های اکسل ساخته‌شده |
| `GET` | `/report-file/<name>` | دانلود فایل اکسل |

نکات:
- فرم افزودن/ویرایش دانشجو **عکس یا ویدیو** هم می‌گیرد (فایل، یا ۴ حالت چهره با وب‌کم راهنمادار) و همه فریم‌های معتبر خودکار به گالری افزوده می‌شوند؛ با این حال `enroll.py` همچنان برای ۶ نمونه از زوایای مختلف دقیق‌تر است.
- `enroll.py` هم وب‌کم و هم `--images`، بعد از ثبت چهره، بهترین فریم را در `photos/student_<id>.jpg` ذخیره و در پنل به‌عنوان عکس نمایش می‌دهد (قبلاً فقط بردارها نگه داشته می‌شدند و عکسی در پنل نبود).
- `monitor.py` فهرست دانشجویان را هنگام شروع می‌خواند؛ بعد از افزودن دانشجو در پنل، آن را یک‌بار restart کنید.

## عکس و ویدیوی دانشجو (آپلود یا وب‌کم راهنمادار)
در فرم افزودن/ویرایش دانشجو یک کادر خاکستری برای تصویر هست؛ سه راه دارید:

- **کشیدن و رها کردن فایل (drag & drop)** روی همان کادر، یا دکمه **«۱. انتخاب فایل (عکس یا ویدیو)»** — عکس آماده (JPEG/PNG) یا **ویدیو** (MP4/WebM). از ویدیو تا ۶ فریم در ثانیه‌های مختلف (۴٪ تا ۹۶٪) جدا می‌شود، هر فریم جدا بررسی می‌شود و فقط فریم‌های دارای چهره واضح نگه داشته می‌شوند.
- **دکمه «۲. ضبط زنده با وب‌کم (۴ حالت چهره)»** — مثل مرحله‌بندی احراز هویت برنامه‌ها، تصویر زنده است و دستور هر مرحله روی همان تصویر نوشته می‌شود:
  1. **رو به دوربین** (چند لحظه ثابت بمانید)
  2. **چرخش به چپ**
  3. **چرخش به راست**
  4. **نگاه به بالا**

  هر مرحله به‌محض اینکه چهره در همان زاویه بیاید **خودکار** ثبت می‌شود و مرحله بعد شروع می‌شود؛ نوار پیشرفت بالا، درصدِ لازمِ چرخش («چرخش سر ۶۲٪ لازم است») و پچ‌نیل نمونه‌های ثبت‌شده نمایش داده می‌شود. با **«ثبت همین حالا»** می‌توانید هر فریم را دستی ثبت کنید و با **«رد کردن این مرحله»** از آن بگذرید؛ با چک‌باکس «ثبت خودکار» می‌توان کل حالت خودکار را خاموش کرد. هیچ مرحله‌ای قفل نمی‌شود.
- **«حذف عکس»** برای پاک کردن عکس ذخیره‌شده.

**زاویه سر** از پنج نقطه چهره (چشم‌ها، بینی، گوشه‌های دهان) در `engine._pose` محاسبه می‌شود و به‌صورت **تغییر نسبی نسبت به فریم اولِ تمام‌رخ** سنجیده می‌شود (`/api/facecheck` فیلدهای `yaw` و `pitch` را برمی‌گرداند)؛ به همین دلیل جای ایستادن یا چپ/راینه بودن دوربین مهم نیست. آستانه‌ها در `dashboard.py` (`CAM_YAW_GATE = 0.12`، `CAM_PITCH_GATE = 0.15`) قابل تنظیم‌اند.

بلافاصله بعد از انتخاب فایل یا ثبت هر فریم، خط رنگی وضعیت چهره نمایش داده می‌شود و نیازی به ذخیره نیست تا بفهمید تصویر به درد تشخیص می‌خورد یا نه:

| رنگ | معنا |
|---|---|
| سبز «چهره واضح … پیدا شد» | عکس قابل استفاده است؛ با «ذخیره» چهره به گالری اضافه می‌شود و دانشجو با `monitor.py` شناسایی می‌شود |
| زرد «چهره خیلی کوچک است» | صورت باید حداقل یک‌سوم عرض کادر را پر کند |
| زرد «چهره تار یا نیمه‌رو» | تمام‌رخ، رو به دوربین، نور مناسب |
| قرمز «چهره‌ای در این تصویر پیدا نشد» | عکس دیگری بفرستید |

در هر دو حالت:
1. اولین (یا بهترین) فریم در `photos/student_<id>.jpg` ذخیره و در ستون `photo` دیتابیس ثبت می‌شود و تصویرش در جدول دانشجویان نمایش داده می‌شود.
2. **همه** فریم‌های معتبر استخراج و به گالری (`data/embeddings.npz`) **افزوده** می‌شوند — یعنی وب‌کم راهنمادار ۴ بردار و ویدیو تا ۶ بردار برای هر نفر می‌سازد؛ یعنی دانشجو بدون اجرای `enroll.py` هم توسط `monitor.py` شناسایی می‌شود و چون زوایای گوناگون ثبت شده، دقت تشخیص در دوربین زنده بهتر می‌شود.
3. اگر در هیچ فریمی چهره قابل استفاده نباشد، عکس ذخیره می‌شود ولی پیام دقیق (کوچک/تار/بدون چهره) نمایش داده می‌شود و چیزی به گالری اضافه نمی‌شود؛ در این حالت `enroll.py` را اجرا کنید. فریمی که کیفیتش پایین باشد از همان مجموعه حذف می‌شود و پیام «N از M حالت به دلیل کیفیت پایین اضافه نشد» نمایش داده می‌شود.
4. در حالت ویرایش، روی پیش‌نمایش برچسب «عکس فعلی» هست و تا وقتی تصویر جدیدی انتخاب نکرده‌اید، عکس قبلی حفظ می‌شود. «حذف عکس» فقط فایل را پاک می‌کند و بردارهای چهره قبلی را نگه می‌دارد؛ «حذف» دانشجو هر دو را پاک می‌کند.
5. دوربین فقط در آدرس امن باز می‌شود؛ `http://127.0.0.1:8050` امن حساب می‌شود ولی `http://localhost` یا IP شبکه ممکن است دسترسی ندهد. پیام خطای دسترسی، با راهنمای Windows Settings › Privacy & security › Camera نمایش داده می‌شود.

بخش **«تست تشخیص چهره»** هم همین مسیر را می‌رود: فایل عکس/ویدیو بدهید یا با «ضبط زنده با وب‌کم» یک فریم همان‌لحظه بگیرید.

> برای دقت بهتر، همچنان `enroll.py` (۶ نمونه از زوایای مختلف) توصیه می‌شود؛ ولی وب‌کم راهنمادارِ پنل همین کار را با ۴ حالت در چند ثانیه انجام می‌دهد.

## گزارش اکسل آخر شب
بخش **«گزارش اکسل آخر شب»** در پنل:
- چک‌باکس ساخت خودکار + ساعت (پیش‌فرض **۲۳:۰۰**). هر روز در آن ساعت فایل `reports/attendance_YYYY-MM-DD.xlsx` ساخته می‌شود؛ اگر آن ساعت سیستم خاموش بود، در اولین اجرای بعد جبران می‌شود (حداکثر ۷ روز عقب). توجه: داشبورد باید در ساعت مقرر در حال اجرا باشد (`run-dashboard.bat`).
- دکمه **«ساخت فایل همین الان»** برای روز انتخاب‌شده در تقویم، و فهرست فایل‌های آماده با لینک دانلود.

محتوای فایل (سه شیت، راست‌به‌چپ، تاریخ شمسی در عنوان):
| شیت | محتوا |
|---|---|
| `گزارش روز` | همه دانشجویان: حاضر/غایب/بدون ورود، اولین ورود، آخرین خروج، مدت حضور، تعداد رویداد مشکوک و **نمودار میله‌ای حضور ۱۴ روز اخیر کنار هر نفر** (`REPT("█")`)؛ ردیف غایبان قرمز |
| `رویدادها` | همه رویدادهای روز با ساعت، شباهت و وضعیت «مجاز/مشکوک» |
| `خلاصه و نمودارها` | ۶ کارت عددی + نمودار میله‌ای تردد ساعتی، نمودار خطی حضور/غیبت ۱۴ روز و نمودار دایره‌ای حاضر/غایب |

ساخت دستی از خط فرمان:
```bash
python export.py                 # امروز
python export.py --date 2026-10-13
```

## تست تشخیص چهره و اعتبارسنجی گالری
پنل **«تست تشخیص چهره»** (بین گزارش اکسل و جدول دانشجویان) دقیقاً همان مسیری را می‌رود که `monitor.py` در دوربین زنده می‌رود، بدون اینکه چیزی ذخیره کند:

1. یک عکس یا ویدیو انتخاب/رها کنید، یا با «ضبط زنده با وب‌کم» یک فریم همان‌لحظه بگیرید.
2. نتیجه: **سبز** = «شناسایی شد: <نام> (<کد>) — شباهت ۹۲٪ · n نمونه چهره در گالری» · **زرد** = کسی به آستانه نرسید و نزدیک‌ترین نفر با درصدش نمایش داده می‌شود · **قرمز** = چهره در عکس قابل استفاده نیست (با دلیل).
3. «آستانه تشخیص» (پیش‌فرض ۰.۴۰ = همان `--threshold` در `monitor.py`) قابل تغییر است تا ببینید با سخت‌گیری/آسان‌گیری چه می‌شود.

دکمه **«اعتبارسنجی گالری (همه دانشجویان)»** جدول می‌دهد: برای هر نفر چند بردار چهره و آیا عکس دارد؛ کسانی که `۰ نمونه` دارند با دوربین **هرگز** شناسایی نمی‌شوند و در جدول دانشجویان هم با برچسب قرمز «۰ — قابل شناسایی نیست» مشخص‌اند.

> اگر تست می‌گوید شما را نمی‌شناسد: عکس رو‌به‌دوربین و نزدیک‌تر بگیرید (برای تست، چهره حداقل یک‌سوم عرض کادر)، سپس در «ویرایش» همان عکس را ثبت کنید تا بردارش به گالری اضافه شود؛ بعد دوباره تست بگیرید.

## تاریخ شمسی و ساعت مجاز ورود/خروج
- انتخاب‌گر تاریخ بالای پنل یک **تقویم شمسی** است (شنبه تا جمعه، پیمایش ماه‌ها و دکمه «امروز»)؛ تبدیل شمسی↔میلادی سمت مرورگر با `Intl` انجام می‌شود و کوئری‌ها به سرور میلادی ارسال می‌شوند. ساعت بالای صفحه و عنوان جدول رویدادها هم شمسی‌اند.
- پنل **«ساعت مجاز ورود و خروج»** دو بازه جدا برای ورود و دو بازه جدا برای خروج می‌گیرد و با یک چک‌باکس فعال/غیرفعال می‌شود. هر رویداد بیرون از بازه‌اش با برچسب **«مشکوک»** و ردیف قرمز در جدول رویدادها نشان داده می‌شود و کارت جداگانه «خارج از ساعت مجاز» آن را می‌شمارد.
- بازه‌ای که از نیمه‌شب می‌گذرد پشتیبانی می‌شود (مثلاً خروج ۲۲:۰۰ تا ۰۲:۰۰).
- تنظیم در جدول `settings` ذخیره می‌شود و روی رویدادهای قبلی هم اعمال می‌گردد؛ یعنی با تغییر بازه، برچسب رکوردهای قدیمی هم عوض می‌شود (در زمان ثبت، مقدار آن قفل نمی‌شود).
- `monitor.py` در لحظه ثبت، رویداد خارج از بازه را با `⚠ خارج از ساعت مجاز — مشکوک` در کنسول و `[OUT-OF-HOURS]` روی تصویر گزارش می‌کند. `report.py` هم ستون `status` با مقادیر `ok`/`suspicious` به CSV اضافه می‌کند.

## منطق ورود/خروج
- **IN**: اولین شناسایی دانشجوئی که نشست باز ندارد ثبت می‌شود (کول‌داون ۶۰ ثانیه برای جلوگیری از تکرار).
- **OUT**: اگر دانشجویی که IN دارد بیش از `--absence-minutes` در دوربین نباشد، خروج خودکار ثبت می‌شود. برای در و خروجگر جداگانه، دو نمونه از `monitor.py` با ایندکس دوربین متفاوت اجرا کنید.

## ساختار پروژه
```
face recognition/
├── database.py      جداول + CRUD (students, attendance, settings) + مهاجرت ستون‌ها
├── engine.py        InsightFace: تشخیص/بردار/تطبیق + گالری npz + face_quality
├── enroll.py        ثبت‌نام چهره از وب‌کم (۶ نمونه) یا پوشه عکس
├── monitor.py       حلقه زنده دوربین: ثبت IN/OUT + پرچم مشکوک
├── report.py        گزارش روز در کنسول + CSV
├── export.py        فایل اکسل گزارش یک روز (۳ شیت + نمودارها) -> reports/
├── dashboard.py     وب‌داشبورد فارسی (Flask + تک‌فایل HTML/JS) + زمان‌بندی گزارش
├── attendance.db    SQLite
├── data/embeddings.npz   گالری بردارهای چهره
├── photos/          عکس student_<id>.jpg (از پنل)
├── reports/         attendance_YYYY-MM-DD.xlsx
├── requirements.txt numpy, opencv-python, onnxruntime, insightface, flask, openpyxl, jdatetime
└── run-dashboard.bat  اجرا/ری‌استارت خودکار داشبورد
```

## فایل‌ها
| فایل | نقش |
|---|---|
| `engine.py` | موتور تشخیص/امضا/تطبیق + گالری بردارها (`data/embeddings.npz`) |
| `database.py` | جداول `students`، `attendance` و `settings` در `attendance.db` + CRUD دانشجو، عکس و طبقه‌بندی ساعت مجاز (مهاجرت خودکار ستون‌های `major`/`email`/`phone`/`photo`) |
| `enroll.py` | ثبت‌نام چهره دانشجو (وب‌کم یا پوشه عکس)؛ **درشت‌ترین فریم را به‌عنوان عکس پروفایل در `photos/` هم ذخیره می‌کند** |
| `monitor.py` | حلقه زنده دوربین و ثبت رویدادها |
| `report.py` | گزارش روز و CSV |
| `export.py` | ساخت فایل اکسل گزارش یک روز (حاضر/غایب + نمودارها) در `reports/` |
| `dashboard.py` | وب‌داشبورد فارسی: تاریخ شمسی، مدیریت دانشجویان با عکس، تنظیم ساعت مجاز، زمان‌بندی گزارش اکسل |
| `photos/` | عکس دانشجویان (`student_<id>.jpg`) که از پنل آپلود یا با دوربین گرفته شده |
| `reports/` | فایل‌های اکسل ساخته‌شده (`attendance_YYYY-MM-DD.xlsx`) |

## تنظیم آستانه
دو عدد مختلف است و جا نزنید:
- **آستانه تشخیص (match)** `--threshold` در `monitor.py` و همان فیلد در پنل «تست تشخیص چهره» (پیش‌فرض ۰.۴۰): شباهت cosine بردار چهره با گالری. کسی شناسایی نشد پایینش بیاورید (۰.۳۵)، اشتباه شناسایی شد بالا ببرید (۰.۵).
- **آستانه کیفیت عکس (detection)** در `engine.py` ثابت‌های `MIN_DET_SCORE = 0.75` و `MIN_FACE_RATIO = 0.15`: تعیین می‌کند یک چهره برای *ثبت در گالری* قابل قبول است یا نه. چهره تمام‌رخ در عکس ۷۲۰ پیکسل معمولاً det_score ≈ ۰.۸۸ می‌گیرد؛ زیر ۰.۷۵ یا کوچک‌تر از ۱۵٪ عرض کادر، عکس ذخیره می‌شود ولی بردار به گالری اضافه نمی‌شود (چون بردار بی‌کیفیت باعث شناسایی غلط می‌شود).
